# 数据类简历的格式规范（外部来源摘编）

用途：用户问「这个模板有什么可学的」、或要重新排版一版时，先照这份核一遍硬指标，再谈措辞。
来源：美国某大学职业中心（William & Mary Career Center）的数据分析简历 checklist、DataCamp 的 data-analyst CV 指南、若干中文项目写法框架。

## 一、硬指标（可直接核对）

| 项 | 规范 | 我们的取值 |
|---|---|---|
| 正文字号 | **≥ 10pt**（DataCamp 推荐 11–12pt） | 10pt |
| 页边距 | **≥ 0.5 英寸 = 12.7mm** | 13mm |
| 篇幅 | 经验 &lt;10 年 → 一页 A4 | 一页 |
| 每条子弹点 | **1–2 行**（约 45–60 字） | 1 行 |
| 阅读时间 | HR 平均扫 **6 秒** | —— |

**推论**：字号与页边距是**下限**，不是可调参数。版面塞不下时先砍内容，再动字号 —— 压到 10pt 以下是拿可读性换版面，招聘方一眼能看出来。
每条要点压到 1 行（中文 ≈ 50 字以内）是同时满足「10pt」与「一页」的唯一办法：超出的部分在 10pt 下会变第 2 行，6 秒扫描时直接被跳过。

## 二、必须有 / 绝不能有

**必须有**

- **一处可验证链接**：GitHub ／ 作品集 ／ LinkedIn。数据分析岗三份指南口径一致地把它列为**必备**，不是加分项。
- **量化结果**：每条成就尽量带数字（规模、提升幅度、处理量）。
- **岗位关键词**：技能栏与成就里的词要与 JD 对得上（ATS 用）。

**绝不能有**

- **个人总结 Summary**（面向应届生与初级岗位的权威口径：`A professional summary or an objective is typically not necessary in an undergraduate or new professionals' resume.`）。
- 无证据的形容词（「显著提升」「丰富经验」）。
- 弱动词开头（黑名单见下）。

## 三、弱动词黑名单（换成动作+结果）

| 不要用 | 换成 |
|---|---|
| 负责 / 协助 / 参与 | 主导 / 设计并交付 / 独立完成 |
| 完成 | 搭建 / 重建 / 交付 |
| 使用 / 会 | 用 X 定位 / 构建 X 模型 / 以 X 交付 |

规律：**弱动词 + 职责描述 → 强动词 + 动作对象 + 方法 + 量化结果**。

## 四、与 SKILL.md 口径的关系

- **「不要 Summary」**（应届／初级岗位）：外部权威口径与实务判断一致，**不要再提议把 Summary 加回来**——它会复述下面已有的学历与经历，招聘官等于读两遍。
- **「课程项目不进一页版」** 与此处「一页」并不冲突：课程项目降级为面试弹药（母版标 `[存档]`），一页只留实习与自己的项目。
- **「饱和式写法」** 与「1–2 行、砍废话」不矛盾：规范反对的是**废话**，不是**内容多**。执行方式是砍形容词、留数字与动作，不是删经历。
- **「精简成一页」与「写到最满」** 这类冲突，摆成选择题（各自代价）让用户拍板，不要自己调和。

## 五、可复用动作：拿别人的模板怎么办

用户丢来一份别人的简历模板／「全网搜索我这个方向的模板」时：

1. 优先取**原文**而非搜索摘要（大学职业中心的 checklist、行业博客的指南原文）。
2. 抽出**可核对的硬指标**（上面第一张表），不要复述「建议突出成果」这类空话。
3. 逐条与**我们当前产出**对照，写成「规范 / 我们 / 差距」三列。
4. 有冲突的地方摆选择题 ＋ 给出自己的倾向，等用户拍板；决定后**回写进那份笔记**并标注「用户选定 X」。
5. 结论落成一份 Obsidian 笔记（`<求职目录>/NN <主题>研究.md`），不要留在聊天里。
