# 数据分析 / 商业分析岗位 · 分档考点库

> 用到这份的场景：给数据方向的岗位出面试备课清单（步骤见 SKILL.md）。
> **这不是全集**——它是按「出现频率」排的。出清单时直接照档位搬，再按用户的简历补几条岗位专属的。
> 其他方向不要往这份里塞，另建 `references/<方向>-question-bank.md`。

## 提问顺序（决定准备顺序）

```
① 实习（有实习就先问实习，问得最久）
   ↓
② 项目
   ↓
③ 技能八股（SQL / 统计 / 工具）
   ↓
④ 手撕 SQL / case 题 / 估算题
```

## 🔴 P0 · 必背（约 4 小时）

### 1. 实习段的每一条口径（每次都是最高优先级）

被问到**任何数字**，第一句先说**口径**，再说数字。这是数据分析面试最大的加分点。

必须提前备好的四类：

| 会被问 | 准备什么 |
|---|---|
| 「数据量/规模」 | 分清**业务侧日增量** vs **你实际经手的量**。别答成「我用 Excel 洗了千万条」 |
| 「去重 / 清洗规则」 | 抬到**口径层**说（「统一多源字段口径」），不展开实现细节 |
| 「准确率 / 覆盖率怎么算的」 | 说清**抽样还是全量**、**分母是什么**。抽样比全量安全 |
| 「对齐 / 匹配规则」 | 能说出一条**具体规则**（一对多怎么办、冲突取哪条） |

### 2. SQL（数据岗唯一会当场动手写的）

按出现频率：执行顺序、JOIN 四种、GROUP BY + HAVING、**窗口函数**、**每组 Top N**；其次去重（`DISTINCT` vs `ROW_NUMBER`）、同比环比、留存/复购率（**先问分母**）、NULL 处理。

- **执行顺序**：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`（所以 WHERE 里不能用 SELECT 的别名）。
- **每组 Top N 定式**：`ROW_NUMBER() OVER (PARTITION BY 分组 ORDER BY 排序 DESC)` 再在外层筛 `rn <= N`。
- **LEFT JOIN 的陷阱**：右表无匹配出 NULL；**一对多会让行数变多**——这跟 Python `merge` 行数膨胀是同一类问题，本质是「先问清楚一行代表什么」。

### 3. 假设检验与 p 值

| 会被问 | 60 分 | 150 分（加层） |
|---|---|---|
| p 值是什么 | 小于 0.05 就拒绝原假设 | **原假设为真**的前提下，观察到当前或更极端结果的概率。**它不是原假设为真的概率**（最常见的误答） |
| 原假设怎么设 | 设成没有差异 | 把**想推翻的**设为原假设 |
| 两类错误 | 弃真、取伪 | α = 误判有效；β = 漏掉真效果；α 定得越小 β 越大 —— 是**取舍** |
| 置信区间怎么解释 | 「真值有 95% 概率落在里面」 | ❌ **这是错的**。正确：重复抽样很多次，约 95% 的区间会包含真值 |
| 样本量不够 | — | 检验力不足，真效果也会被判成不显著 → 要先算样本量再开跑 |

### 4. A/B 实验

- **样本量四个输入**：基线转化率、最小可检测效应（MDE）、显著性水平 α、检验力 1−β。面试官要听的是你知道有这几个输入。
- **多重比较**：先定一个主指标，其余作护栏指标；或做校正。
- **分流要用户级**，不要会话级。
- **显著 ≠ 上线**：还要看新颖效应、辛普森悖论、护栏指标。
- 高频的其实是「**你做过 A/B 吗**」——备一个**具体的实验设计**（指标 / 分组 / 跑多久 / 怎么看），哪怕来自课程案例。

### 5. 指标口径与漏斗 + 异常排查

- **任何一个比率，先说分子分母。** 不同公司口径不一样，不确定就**问清楚再算**。
- **漏斗**：定义环节 → 算环节转化率与整体转化率 → 找最大流失 → 说清「定位到断点」不等于「解决了问题」。
- **异常排查（超高频业务题，「某天 GMV 掉了 20% 怎么办」）**：
  ① 先确认**是不是数据问题**（埋点 / 口径 / 统计延迟）→ ② **拆维度定位**（渠道 / 城市 / 品类 / 新老用户）→ ③ **对比时间**（同比、环比、与前一天）→ ④ **外部原因**（活动结束、竞品、季节、舆情）→ ⑤ 给结论和建议。
  **不要一上来就猜原因——先拆解。** 面试官看的是这个顺序。

## 🟠 P1 · 高频（约 6 小时）

| 考点 | 要答到什么程度 |
|---|---|
| **回归** | OLS 假设、R² vs 调整 R²、多重共线性（VIF）、残差图看什么（异方差 / 非线性）、**什么时候不能用线性回归**（因变量 0/1 → 逻辑回归） |
| **描述统计** | 均值 / 中位数 / 标准差 / 分位数；**什么时候必须用中位数**（长尾分布）；箱线图看什么 |
| **Excel / Power Query** | 合并查询 vs 追加查询、**表间关系怎么定**（粒度、一对多、方向）、哪一步最容易出错；VLOOKUP vs XLOOKUP；透视表 |
| **BI 图表选型** | 趋势→折线、对比→柱状、占比→堆叠（饼图慎用）、分布→直方图/箱线、相关→散点、漏斗→漏斗图。被问「做过几张看板」要能说**谁在用、多久更新** |
| **Python pandas** | `read_csv / drop_duplicates / groupby().agg() / merge / fillna / pivot_table`；要能说**一个自己踩过的坑**（如 merge 后行数变多） |
| **数据清洗** | 缺失值（删除 / 填补 / 标记）、异常值（3σ / IQR）、重复值、类型不一致。加一句「清洗前先看分布，不盲填」 |
| **Case / 估算** | 费米估算：拆公式（人口 × 渗透率 × 频次）→ 逐项估数 → 说明哪个假设最敏感 |

## 🟡 P2 · 加分（约 4 小时）

| 考点 | 一句话准备 |
|---|---|
| **辛普森悖论** | 分组看不显著、合起来显著（或反过来）——分组权重不同。**举自己的例子** |
| **相关 ≠ 因果** | 混淆变量、反向因果、选择性偏差；进阶提一句随机实验是金标准 |
| **kNN** | k 怎么选、距离度量、维度灾难 |
| **朴素贝叶斯** | 条件独立假设、为什么适合文本 |
| **线性规划** | 决策变量 / 目标函数 / 约束；**影子价格 = 该约束放宽一单位的边际收益**；敏感性分析看什么 |
| **GitHub 项目** | 面试官可能真会点开。README 能读懂、代码能跑、**有数据字典**。被问「怎么想到做这个」答**痛点**，不是「为了写简历」 |

| 手撕算法（LeetCode 中等以上） | 数据岗基本不考。面到就直说「这块我刷得少，能不能换个方向的题」——实习生面试完全可以 |

## case 题的通用骨架（三个动作）

1. **先澄清**：分母是什么？时间范围？口径怎么定？（面试官往往故意不给全，看你会不会问）
2. **给框架**：把问题拆成 2–4 个可验证的子问题，说「我打算这样拆」。
3. **落到数据**：每个子问题需要什么表、什么字段、怎么切维度；**主动说哪个环节拿不到数据**。

> 这个骨架配上 SKILL.md 的「为什么需要 → 两种方案 → 为什么选这个 → 如果重来」，
> 足够应付绝大多数 case 面，不用背题型。
