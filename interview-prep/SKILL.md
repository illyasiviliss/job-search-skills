# 面试备战与复盘（Interview Prep）

面向「投出去一批、面试一场接一场」的求职期。**核心不是把技术学通，是把面试官会问的那几十道题答到加分。**

## When to Use （何时使用）

- 用户说「准备面试 / 面试要问什么 / 出个拷打指南 / 八股怎么背」。
- 拿到面试通知，要压缩准备时间。
- 某场面试结束后说「今天被问了 X 没答上来」→ 走复盘流程（本文末）。

不适用：写简历 / 定投递版本（`cv-master`）、判断岗位值不值得投（`job-search-method`）。

## 四条底层定理（先跟用户对齐，再动手）

移植自「混子导向速成实习」方法论（B 站 `BV1rrVd6fEsm` 思路篇 / `BV1EhJu6kEZG` 实践篇）。
原视频讲的是 Java 后端速成，**方法论可移植，具体操作不必照搬**（比如它的「买个商业项目写简历」多数人没必要——手上有真材料就别编）。

1. **找实习是「通过性」制度，不是「选拔性」。** 像期末考不像高考：70 分和 80 分拿的是同一个 offer。
   所以目标不是「学通 SQL」，是「把会被问的那几道答漂亮」。
2. **实习极看运气 → 用数量对抗概率。** 海投是**所有环节里最重要的一步**。
   **先投再准备** —— 准备到完美才投，等于晚一轮，少一场能告诉你缺什么的面试。
3. **面试本身是最重要的信息源。** 早面、多面。一直准备不敢面 = 在没人问的地方浪费时间。
   「面试不是期末，是随堂小测」。
4. **面试官照着简历问。** 简历就是出题范围。**想被问什么就往简历上写什么**，写了就必须 100% 准备。

## 步骤

1. **先定提问顺序，再定准备顺序。** 顺序固定：
   `实习 → 项目 → 技能八股 → 手撕 / case`（有实习就先问实习，且问得最久）。
   推论：**简历里最重的那一段，必须是准备得最细的那一段**（段落权重见 `cv-master`）。
2. **从简历列题，不另起题库。** 逐字扫一遍简历，每条能出题的话都列出来，再分档。
3. **分档 + 时间预算 + 不准备清单。**
   - 🔴 **P0 必背**（几乎每场）｜🟠 **P1 高频**（约半数场次）｜🟡 **P2 加分**（问到就赚）｜⚪️ **明确不准备**。
   - **必须给总时长**（用户要的是「方便压缩准备时间」），默认 14 小时量级：P0 约 4h、P1 约 6h、P2 约 4h。
   - **⚪️「不准备什么」和「准备什么」一样重要**，必须单独列一节。省下的就是赚的。
   - 每档再落到「Day 1 上午 / 下午」这种可执行的时段表。
4. **每条给四格**：会被问什么 → 你要答的要点 → 60 分答案 → 150 分答案。
5. **写埋钩子脚本**（自我介绍 ＋ 项目介绍），把要放慢加重的词标出来。
6. **交付**：一份独立笔记（`NN <方向>面试拷打应对指南.md`），并**替用户打开**。
7. **复盘回填**（见下节）。

## 60 分 vs 150 分（本技能最核心的答法）

同一个问题两种打法。差的就是多背十条八股。

- **60 分**：是什么 ＋ 怎么做。
- **150 分**：在它前面补三层，后面补一层：

  > **为什么需要 → 两种方案 → 为什么选这个（约束是什么）→ 假设写进文档 → 如果重来会怎么改**

- 再加一条：**主动说局限**。说「这里默认了 X，当时拿不到 Y，是已知的妥协」，是加分不是示弱。

这一套能套在**任何一个**技术选择上（去重口径、归一化分母、图表选型、模型选择）。
演练时用简历里的**真实素材**，不要用教科书的例子。

## 埋钩子（每场都用得上）

面试官通常是**边听你讲、边翻简历**。你**放慢、加重**的那几个词，他一定会追着问。

- 自我介绍与项目介绍里，埋 **2–3 个**你精心准备过的点（语速放慢 + 音量提高）。他一旦顺着问，就进了你的主场。
- **不擅长的部分快速带过、绝不主动提** —— 不提，大概率不会被问（定理 4）。
- 钩子要具体到可追问的层面（说「指标口径」而不是「数据分析」）。

## 复盘（每场必做 —— 这是闭环）

若用户采用了「饱和式写法 ＋ 用真实面试当校准器」的路线（见 `cv-master`），面后的回填不是记录，是**当天补强清单的来源**。

- 回填进**已有的演练表**，**不要另开一份**。
- 每场填四格：日期 / 公司 / **被问穿的是哪一句** / 问到第几层 / 补了什么。
- 同一句被问穿两次 → 直接进 P0，并给一个可执行的补强动作。

## 坑

- **别交「百科全书」式题库。** 用户的时间有限，**分档 ＋ 时间预算 ＋ 不准备清单**才是要的交付形态。一份列全所有八股的文档他不会看。
- **别把某个方向的题库当通用题库发给另一个方向。** 按投递方向分别建笔记（`NN <方向>面试拷打应对指南.md`）。
- **手撕环节（SQL／算法）写不出来时，不要直接说「我不会」**：① 嘴不要停，边说思路边敲；② 听面试官的暗示——他递的那句话通常就是答案；③ 最后没跑通就**口述完整逻辑**，说「思路我清楚，是语法没写顺手」，而不是放弃。
- **业务／case 题不要一上来猜原因**。先**拆维度定位**（渠道／城市／品类／新老用户 → 再看时间对比 → 再找外部原因），最后才给结论。面试官看的是这个顺序，不是那个答案。
- **不要替用户改简历去迁就面试。** 面试暴露的缺口进演练表和补强路线，**不进简历降级**（见 `cv-master` 的「简历策略」一节）。
