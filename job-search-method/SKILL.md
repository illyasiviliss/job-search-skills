# 求职双边画像：偏好画像 + 真实画像

本技能管两件事，且必须**分开**——把「值不值得投」和「拿不拿得到」拆成两份文件，是这套方法最核心的设计：

| 画像 | 用途 | 谁能看 |
|---|---|---|
| **偏好画像**（值不值得投） | 判断岗位与用户的口味是否匹配 | 只给用户与 agent 看 |
| **真实画像**（拿不拿得到） | 判断难度、缺口、实话建议 | **仅内部，绝不外传** |
| 母版（对外材料） | 简历唯一真相源 | → `cv-master` |

**三条铁律**：① 对外材料只用母版；② 内部分析只用真实画像；③ 两者永不混用、永不互相回写。

> ⚠️ **真实画像是这套体系里最敏感的文件**：里面写着用户自述的短板与未证实的技能。它**不进简历、不进投递材料、不给任何第三方看**。公开或误传会直接毁掉求职。

## 岗位线索池

路径自定（建议 `<求职目录>/05 岗位线索（<赛道>）.md`），**一个赛道一份**。

- **追加不覆盖**：每次搜索后新建一个带日期的区块，历史区块永不改写。
- **状态标记就地改**：🟢 现在开着 ／ 🟡 季节性（每年固定档期）／ 🔴 与红线冲突（列出备查）／ ⏳ 需核实。
- 线索池只存**事实**（截止日、门槛、链接、名额）；**判断留在偏好画像**，别把结论写进线索池。
- 文件头写清两条元条件：**身份可用的通道**（户籍／签证／应届身份等）与用户的**优先级排序**（如「氛围 ＞ 薪资」）。

## 文件体系（动手前先看这一层，别在聊天里另起一套）

```text
求职/
├── 00 工作台.md            # 大步骤、卡点、板块状态（每日梳理的入口）
├── 01 母版体检报告.md       # → cv-master
├── 02 待补事实.md           # [待补] 清单，用户直接在这里填
├── 03 偏好画像.md           # 本技能
├── 04 真实画像（内部）.md    # 本技能，绝不出现在对外材料
├── 05 岗位线索（<赛道>）.md  # 线索池：追加不覆盖，一个赛道一份
├── 06 JD对照（<目标>）.md    # 目标 JD × 母版逐条对照
├── 07 投递台账.md           # 状态机（状态/下一步/谁做）
├── 08 求职拆解（动作级）.md  # 大步骤 → 动作级
├── 09 决策研究（<主题>）.md  # 决策点的判据与依据
└── NN 面试准备 / 项目 / 工作台 …
```

- 文件名带主题后缀，**按前缀 `NN` 定位**（用 search_files，不要背全名）。
- **新赛道另开线索文件，取下一个未用前缀**。**重命名或删除这些文件时，同步改本节的清单与引用它的文件**（旧名一旦留下就会让下一个会话去找不存在的文件）。
- **投递台账是唯一状态口径**：每条写「状态 / 下一步 / 谁做」。任何投递、笔试、面试、回复后**立刻更新它**——否则次日的定时梳理会照旧状态排活。
- **投前先把公司 FAQ 读完，它改的是投递顺序而不是细节**：一次性规则（投递后不可改简历/职位、在职实习生不得同时投校招、提前批投过不能再投正式批、每人 N 个平行志愿）都是决策输入 —— 「先实习还是直接校招」「志愿怎么排」「什么时候定稿」全由它们决定。读不到就把这些列成投前确认项，别默认按常规流程走。
- **决策与任务分开**：决策点写成「**判据 → 选项 → 默认值**」放进 08；用户说「我不了解，先详细研究给我」时，产出一份研究文件交他定，**不要替他拍板**，也不要把没定的决策当成待办塞进清单。
- **投递前先跑一次 DDL 检查**：把候选清单里的「截止」全部与今天比对——**近三天到期的排最前，已过期的当场剔出主表**，并保留一行「已剔除（别再投）＋原因」。只写「尽快投递」的行不能当成没有截止，仍要回官网核一次。
- **候选池到短名单的筛选口径要写进表头**（例：「★ ＝ JD 明确写有数据分析/商业分析类关键词」）：用户下次看名单时不用问「这些是怎么选的」。
- **用户的批注写在文件里，不在聊天里**。他可能用荧光笔（`<mark style="background:#abf7f7">`）、直接写进「✍️」区、把整段删掉、或在段间插一行编号意见。他说「我改了 / 你看看」时，**先 read_file 找出全部批注再开口**，不要问他「你想改哪里」，也不要只回应其中一条。
- **改这些文件优先用定点 patch**；要整体重写时，必须在**同一轮先 read_file 再 write_file**。
- **海投作战表是固定的产出形状**（用户说「先投 N 家」时直接照这个做）：一行一家，字段固定为 `# / 公司 / 企业性质 / 地点 / **用哪版简历** / 截止 / 投递链接`，后面再挂两张附表——「岗位（原表原文节选）」与「**已剔除（别再投）＋原因**」。**必须带「用哪版简历」一列**（对多版简历的子工作台），否则投的时候要回头查。表头写死：分批投（每批 15–20 家、隔 2–3 天）＋同集团同系统只投 1–2 个岗的自检三问。
- **部门/职能拆解属「我的合理解释」而非官方描述**：文件头必须标来源与不确定性，并把「哪几个部门真的开放给轮岗生」这类问题列成**当场确认项**，别当事实交付。

## 偏好画像：结构

五段固定结构，**每条都要能对着岗位描述核实**（可观察，不写内心感受）：

1. **摘要** —— 2–3 句，把理想岗位说成人话。
2. **必须满足 / 红线** —— 硬门槛与见到就跳过的信号（分开写，「不要什么」比「要什么」更能定位）。
3. **强偏好** —— 会显著影响选择，但非一票否决。
4. **可要有可没有** —— 不算决策因素。
5. **已确认结论 + 观察记录表 + 待确认问题** —— 见下面的更新机制。

**重要：把判断锚定在「交付物」上。** 岗位名称骗人（叫「数据分析」的可能天天写 PPT）。判断顺序固定为：
**实际交付物 → 雇主类型 → 岗位名称**。

**一个常见的深层判据（可直接问用户）**：真正的红线往往不是「商业/业务岗」本身，而是**「没有验证环节的空洞输出」**（空画 PPT、没落地的研报、只做材料整合与汇报）。
合格的检验方式两种任一即可：**数据可验证**（模型／策略／指标口径／数据产品）**或业务可验证**（渠道与经销商、动销与业绩、真实客户）。
用这个判据去筛，比按岗位名称筛准得多。

## 真实画像：结构

- 顶部写清「仅内部使用、不混入对外材料、不主动披露」。
- **母版条目 × 真实情况对照表**：用户说一条记一条，未说明的留 `⏳ 待确认`，**不自行推断**。
- 真实短板（缺口）与真实强项分开列 —— 强项也要真实，因为它同样决定能不能拿到面试。

## 更新机制（每次对话都要跑）

**四个触发点**：用户做出选择 / 给出纠正 / 自述经历细节 / 一次面试或投递有结果。

1. **先读，再写**。任何求职对话开始前先读两份画像；更新是「读—补 diff—确认」，不是覆盖。
2. **每条都带证据与强度**：
   - `强信号`：用户明确说出偏好，或同一模式出现 ≥3 次。
   - `中信号`：一次性行为选择（标黄某家、跳过某家）。
   - `弱信号`：从语气/迟疑里猜的 —— **写进观察表，不写进结论**。
3. **升级规则**：只有「用户亲口确认」或「≥3 次独立观察」才能进「已确认结论」区。其余留在观察表。
4. **纠正优先**：用户说「不是这样」时，立刻改写对应结论，并在观察表留一行「旧结论 → 新结论 + 日期」，**不要静默覆盖**。
5. **每季度（或用户换方向时）回头审**：把长期没被推翻的中信号升级，把与现状矛盾的结论标注过期。
6. **矛盾答案 = 信息缺口，不是偏好冲突**：用户在多选里同时选了互斥项时，先看是不是**他不懂那个术语**（他会在此时反问术语）—— 先用人话解释术语（对象 + 时长 + 对他意味着什么），再重问一次，**不要**据此改画像，也**不要**把矛盾项都当成他的两个偏好写进偏好画像。

## 输出纪律

- 更新完**当次就报一句**改了哪条（一句话，不写报告）。
- 从画像推出建议时，**要用用户的原话/他的选择当证据**（「你标了 A 却没标 B，两者差别在交付物」），不要只说感受。
- 判断「值不值得投」给三档：**值得优先 / 可以看看 / 跳过**，并写一句理由。
- 不做心理分析，不给用户贴人格标签；只记与求职决策有关的可观察事实。

## 用户的自述 ≠ 对外措辞（不替他降级，也不回写母版）

- 用户自述的技能／经历真实水平 → **只写进真实画像**，**永不回写母版**。
- 他若选择「**母版保留原样**」，留档这个决定（哪一天、原因），同时把「让简历变真」的补强路线写进投递台账 —— **让简历变真是解法，不是改措辞**。
- 反过来：**不得自行把他写在简历上的能力降级、加限定语或删除**；措辞诚实与否是他的决定。
- **但他亲口降级的条目不在此限**：这类**已确认**的降级当次就写进真实画像的对照行并标「已确认」——不要因为「怕替他降级」而让它停在 ⏳ 待确认，也不要下轮再问一遍。
- **母版怎么改仍由用户定**：审计出「写了但答不出来」的冲突后列成表交他选（做法见 `cv-master` 的一致性审计），不自行删改。
- **若用户选了「饱和式写法」路线**（见 `cv-master`），则**不再提「诚实版」「在补」「技能栏不写会问穿」这类建议**。正确的配合方式是：把简历写到最大，同时交付「技能追问演练」（把每句拆成追问层级 1 名词／2 机制／3 取舍，标出缺口与补法）。配套动作：每次面试后把「被问穿的是哪一句、问到第几层」回填演练表。唯一保留的约束是「不新增编造内容」。

## When to Use（何时使用）

- 用户问「这个岗位适合我吗 / 值不值得投 / 我该去哪家」。
- 用户做出一次选择：标黄、跳过、投递、放弃面试、收到反馈。
- 用户纠正你的判断（「不是这样的，我其实…」）。
- 用户问「你了解我吗 / 你觉得我想要什么」。
- 和用户一起筛公司名单 / 招聘会名单 / 岗位清单（先读画像，别凭印象筛）。

不适用：写简历与投递（→ `cv-master`）。

## 检索类任务

用户说「帮我找 X 类岗位 / 有什么实习机会 / 某类公司招人吗」时，**先读 [`references/job-listing-research.md`](references/job-listing-research.md)**：收窄类别的问法、检索通道实况、聚合页三条坑、红旗过滤、**中小企业四条通道与海投纪律**、落库与汇报格式都在里面，别临场重搜一遍。
